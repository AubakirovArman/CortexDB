# A6.4 — Honest ERB run through the engine product path

This is the honest exit-proof record for A6.4 of
[`NEXT_GEN_MASTER_PLAN.md`](NEXT_GEN_MASTER_PLAN.md): a real EnterpriseRAG-Bench
retrieval measurement taken **through the `cortex_engine::Database` product
path**, not a bespoke offline scorer. "Honest" here is load-bearing — the point
of the task is to record what the product path actually does today, including
where it falls short of the exit bar, rather than rounding it up to "done".

## What was measured

The bench binary `enterprise_rag_bench_retrieval` ingests the full ERB corpus
into a fresh `cortex_engine::Database`, checkpoints it, and serves retrieval for
the balanced-50 question set entirely through the engine. The runner identifies
itself in the report as `cortex-engine-keyword-source-aware-retrieval` — i.e.
the engine's default lexical/source-aware retrieval path.

- Corpus ingested through the engine: **511,958 documents** (full corpus, not a
  slice).
- Questions: **balanced-50** (the type-stratified ERB subset).
- Reproduce: `make enterprise-rag-bench-cortexdb-retrieval-50` (release build,
  `--reset-db`, no `--max-documents` cap → full corpus). The pipeline was
  re-verified end-to-end on 2026-07-02 via the bounded
  `enterprise-rag-bench-cortexdb-retrieval-smoke` (500-doc slice, exit 0): the
  engine opens, ingests, checkpoints, and serves all 50 questions cleanly. The
  smoke's *recall* is deliberately **not** cited — a 500-of-511,958-doc slice
  cannot contain most gold documents, so only the full-corpus numbers below are
  meaningful.

Artifacts (under `target/`, gitignored, regenerated by the target above):
`retrieval/cortexdb_balanced_50_report.json` (run provenance) and
`retrieval/cortexdb_balanced_50_metrics.json` (official ERB
`metrics_based_eval` document-recall scoring).

## What this proves, and what it does not

**Proven.** The engine product path runs the benchmark end-to-end at full corpus
scale and retrieves the gold document for the majority of factual questions
(basic 76.5%, reasoning 75%, conflicting-info 100%). The measurement is
reproducible from a committed make target.

**Not yet at the exit bar.** Overall recall@10 (56.35%) is **below** the plan's
≥75% retrieval exit target. The deficit is concentrated in exactly two pools —
`semantic` (23.1%) and `project_related` (24.7%) — which is consistent with the
A2.0 finding in [`EMBEDDING_MODEL_SELECTION.md`](EMBEDDING_MODEL_SELECTION.md)
that a dense embedding pass alone does not fix the semantic pool. Closing this
gap is what the still-open plan dependencies target: A1.4 (weight
re-derivation), A4.2 (temporal supersession), and A7.2 (two-stage retrieve).
The A-track slices landed this cycle (graph-descent HNSW A3.1, MMR A5, temporal
window A4.1, guarded-recall A3.3) are **default-off** and not yet wired into
this bench path, so they do not move this number — the remaining wiring (A7.2
two-stage retrieve; A5/A4.1 as AQL surfaces) is the honest integration gap.

**Answer quality is unmeasured here.** This is a retrieval-only run, so
`average_correctness_pct` and the combined correctness/completeness score are
`0.0` by construction — no LLM answer was generated or judged. The full
answer+judge combined-score exit-proof (Gemma answer generation + judge over the
official set) remains the outstanding external step; it is expensive and is not
run as part of this record.

## Exit-proof status

Honest verdict: the engine product path is **wired and reproducible**, factual
retrieval is strong, but the retrieval exit bar (≥75% recall@10) is **not yet
met** (56.35%), and the answer-quality half of the exit-proof is **not yet
measured**. A6.4 is therefore recorded as *measured, not passing* — the honest
outcome the task exists to surface.
